# 界面行为契约

> 状态：v0.1（macOS 已按本文实现；Windows 实现时逐条对照）
> 关联：执行计划 S2-5、S4-10、S5-3

本文约束**行为**（提示时机、措辞、可取消性、错误层级），不约束视觉细节。两端可以长得不一样，但不能对同一个危险操作给出不同承诺。

## 1. 危险操作的确认

### 1.1 必须确认

| 操作 | 确认文案（标题） | 正文必须包含 | 按钮 |
|---|---|---|---|
| 还原本地修改 | 「还原 N 个路径的本地修改」 | 将丢失的文件列表；说明未纳入版本控制的文件不受影响 | 还原（destructive）/ 取消 |
| 删除并纳入提交 | 「删除「X」并纳入版本控制」 | 将一并丢失的本地修改列表 | 删除（destructive）/ 取消 |
| 冲突解决（mine-full / theirs-full / base） | 「解决冲突：<path>」 | 该策略的**人话后果**（见下） | 确认解决（destructive）/ 取消 |
| 批量解决冲突（多于 1 个文件，含 working） | 「解决 N 个冲突」 | 策略后果、将要处理的文件列表（超过 8 个折叠）、"解决前会备份" | 确认解决 / 取消 |
| 清除全部凭据 | 「清除所有已保存的仓库凭据？」 | 下次需要重新登录 | 清除（destructive）/ 取消 |

### 1.2 冲突策略的人话解释（不得只显示参数名）

菜单项只显示"菜单标题"一列；`--accept` 的原始 token 只能出现在诊断日志里。

| 策略 | 菜单标题 | 确认框正文 |
|---|---|---|
| `working` | 保留当前内容，仅清除冲突标记 | 保留磁盘上的当前内容（可能仍含冲突标记），仅清除冲突状态。 |
| `mine-full` | 用我的版本覆盖（丢弃服务器改动） | 丢弃服务器带来的修改，只保留本地版本。此操作不可撤销。 |
| `theirs-full` | 用服务器版本覆盖（丢弃我的改动） | 丢弃全部本地修改，改用服务器版本。此操作不可撤销。 |
| `base` | 恢复基线版本（丢弃双方改动） | 还原到冲突前的基线版本，本地与该次服务器修改都会被丢弃。 |

### 1.3 确认的实现位置

确认不只是界面动作：服务层的 `confirmed` 参数是必须的。界面在调用前先取 `OperationPreview`，把 `detail` 原文展示给用户；用户确认后带 `confirmed: true` 重新调用。

### 1.4 解决后的结果提示

解决完成必须弹一次**非错误**提示（不是"操作失败"弹窗），内容：

- 备份位置，并提供"在 Finder 中显示备份"；
- 若 `ResolveOutcome.pathsWithResidualMarkers` 非空，标题改为「已标记为已解决，但仍有 N 个文件含冲突标记」，
  逐条列出文件与行号，并写明"直接提交会把标记写进仓库"；
- 跳过的文件（二进制、非 UTF-8、超过 8 MB）如实计数，不得静默忽略。

## 2. 进度与取消

| 场景 | 要求 |
|---|---|
| checkout / update / commit | 必须进入任务中心，展示当前输出行；可取消 |
| status / info / log / diff | 可后台执行，不进入任务中心；超过 1 秒显示加载态 |
| 取消 | 按钮立即生效，子进程 SIGTERM → 2 秒 → SIGKILL；任务条目状态变“已取消” |
| 取消后的提示 | update 取消后提示“工作副本可能处于中间状态，必要时执行 Cleanup” |
| 失败 | 任务条目保留，显示错误摘要，可展开查看脱敏诊断 |
| 失败后的重试 | 条目提供“重试”，语义是**重跑同一次请求**；重试不得绕过服务层的确认参数，也不得自动重试 |

重试与认证流程里的“重试一次”不是同一件事：认证是对同一个失败请求换凭据后再试一次，由流程自动完成；任务中心的重试是用户判断外部条件已恢复后主动发起，次数不限，每次都重新计入 `attempts`。成功的条目不再提供重试——它没有可重放的内容。

任务条目不得在完成后立即消失（用户需要回看失败原因），由用户手动“清除已完成”。

## 3. 错误呈现层级

| 分级 | 呈现 | 要求 |
|---|---|---|
| recoverable | 顶部内联提示条 / 轻量弹窗 | 带“重试”入口；不遮挡主要内容 |
| needsUserAction | 模态表单（认证）或确认对话框 | 必须给出下一步动作，不能只显示错误 |
| fatal | 弹窗 + 可复制诊断 | 显示应用错误码（如 `SVN-0004`）与 svn token |
| 解析失败 | 弹窗 | 提示可能是 svn 版本不兼容，给出“复制诊断信息” |

任何错误弹窗都不得包含密码、URL userinfo、`--password` 值。

## 4. 认证流程

1. 首次操作不带凭据；
2. 需要认证时弹出表单，标题「需要认证」，副标题显示主机名；
3. 表单说明“凭据只保存在 macOS 钥匙串；密码通过标准输入传递”；
4. 用户提交后**只重试一次**；
5. 取消则回到原界面，保留错误提示，不循环弹窗。

## 5. 页面与信息架构（MVP）

| 页面 | 必须包含 | 不得包含 |
|---|---|---|
| 变更 | 按冲突/修改/新增/删除/未版本控制分组；多选；双击看差异；Add / Delete / Revert / Resolve 入口 | 隐藏的批量操作 |
| 提交 | 勾选列表、提交说明、空说明禁用提交、冲突横幅、提交前状态复核 | 自动勾选冲突项 |
| 历史 | 分页加载、作者/时间/说明、变更路径、按修订看差异 | 一次性加载全部历史 |
| 差异 | 逐行着色、大文件截断提示、复制 | 阻塞主线程渲染超大 diff |
| 信息 | URL、仓库根、修订、最后修改、仓库锁 | 显示密码或 token |
| 设置 | svn 路径、版本来源、超时、清除凭据 | 显示已保存的密码 |

## 6. 空状态与不可用状态

- 无工作副本：欢迎页，提供“添加”与“检出”两个入口。
- 工作副本干净：明确写“工作副本干净”，不要空白。
- svn 不可用：主界面可打开，但所有操作入口禁用，并提供“打开设置”。不得静默失败。
- 目录已被删除/移动：条目保留但标记失效，提示移除或重新定位。

## 8. 日志与诊断

日志是给支持用的，不是给用户读的；但它的可见性必须在界面上说明白。

| 项目 | 约定 |
|---|---|
| 位置 | `~/Library/Logs/OpenSVN/opensvn.log`，设置页显示完整路径并可一键打开目录 |
| 级别 | 关闭 / 仅错误 / 错误与警告 / 常规 / 调试，默认“常规”；调试级别记录每条命令与输出 |
| 内容 | 命令（提交说明与文件内容以占位符替代）、退出码、耗时、失败时的 stderr 摘要 |
| 脱敏 | 每一行在写盘前经过 `LogRedactor`；URL userinfo、`--password`、token 一律替换为 `***` |
| 轮转 | 单个文件 2 MB，保留 2 个旧文件；日志损坏或目录只读时**不得**影响任何操作 |
| 默认关闭 | 未调用 `configure` 的进程（单元测试、probe）不写任何日志 |

“记录了什么”本身就是隐私承诺。提交说明属于用户内容，不写进日志；需要排查提交问题时，命令中只保留 `-m <message>` 的形式。
