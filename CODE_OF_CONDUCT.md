# Code of Conduct

## Scope

This applies to issues, pull requests, commit messages, code review, and any
project space (chat, mailing list, conference booth) where someone is
representing OpenSVN.

## Expected behaviour

- Assume the other person is competent and acting in good faith. Ask what they
  meant before concluding they were careless.
- Critique the change, not the person. "This parser assumes `LC_ALL=C`, which
  breaks non-ASCII paths" is useful; "you clearly don't understand i18n" is not.
- Accept that maintainers say no. A declined PR is a scope decision, usually
  about the contract or the roadmap, not a verdict on your ability.
- Respect that this project touches other people's version-controlled work.
  Careless data-loss bugs are a conduct problem, not just a technical one.
- Give credit for ideas and code you build on.

## Unacceptable behaviour

- Harassment, insults, sexualised attention, or sustained disruption.
- Discriminatory comments about race, ethnicity, nationality, gender, gender
  identity, sexual orientation, disability, age, religion, or appearance.
- Publishing someone's private information without permission.
- Deliberately submitting code that damages users' working copies, harvests
  credentials, or exfiltrates repository contents.

## Reporting

Report to `conduct@opensvn.example` (placeholder domain until the project
publishes its real contact — track this in `docs/development/decisions/`).
Reports are read by the maintainers only. Include what happened, where, and who
was involved; screenshots or links help.

Maintainers will acknowledge within 5 working days and explain what happens next.
Consequences scale with severity and repetition: a private clarification, a
public correction, temporary removal from project spaces, or a permanent ban.
